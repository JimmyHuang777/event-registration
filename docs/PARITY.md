# 手機（LIFF）與 Dashboard 對照

這份文件專門記錄**兩邊的差異**。原則見 DECISIONS `D-早期-01`：每個功能兩邊都要有，例外要明列並經使用者同意。
差異分三類：

- ✅ **刻意不同**：已列入例外，兩邊用途本來就不同。
- ⚠ **待決定**：目前只有一邊有，但**沒有列入例外**，需要你決定要補另一邊、還是正式列為例外。
- ➕ **形式不同**：兩邊都有，但做法或能力不同（例如 LIFF 逐筆處理、Dashboard 批次）。

資料來源：`CODEMAP.md` 第 6 節（資料表寫入能力，自動產生）＋ 表單欄位逐項比對（活動、工作範本、流程表）＋ 程式查證。最後核對日期：2026-10-09。

## 三、兩邊都有、形式不同（➕）

| 功能 | 手機（LIFF） | Dashboard |
|---|---|---|
| 活動建立／編輯 | `event-admin.html`＋`events-admin-api.save_event` | 「新增活動／管理活動」直接寫資料庫；欄位相同：名稱、描述、日期、地點、連結代碼、所屬壇、近期重要班程、自訂報名欄位、適用群組（P-09 除外） |
| 工作範本 | `tasks-admin.html`；欄位相同（頻率、星期／每月日、地點、所屬壇、近期重要班程、日期、起迄日期、子項目、適用群組） | 同欄位，另有 Word／Excel 匯入、匯入檢核表 |
| 流程表（開班課程表） | `activity-flow-admin.html`；欄位相同 | 同欄位 |
| 壇各組：組員／6W／交接 | 檢視與編輯 | 檢視與編輯；另有 6W 匯入 |
| 壇各組：整組對調 | 組長**提出→對方同意→執行** | 管理者**直接執行** |
| 活動欄位建立器：欄位名稱「住宿」自動帶入內宿／外宿 | `event-admin.html` | Dashboard 新增／編輯活動 |
| 管理者權限矩陣（活動、工作、共乘、住宿、會議、流程管理者） | `tasks-admin.html` 的「管理者權限」（`perms_set`，寫入同樣六張表） | 「管理者權限」畫面 |
| 共乘、住宿 | 司機／房東建立與管理自己的資料、乘客提出需求 | 管理者做媒合、刪除，並管理「車管理者／住宿管理者」名單 |
| 個人資料與親友資訊 | 本人編輯（`profile-api`） | 只讀＋匯出 CSV |
| 報名 | 本人報名、修改、取消 | 管理者檢視與處理 |
| 工作認領與完成 | 組員認領、完成（`tasks-api`） | 管理者指派、檢視統計、匯出指派清單 |

## 四、怎麼維護這份文件

1. **新增或修改功能時**：在同一次交付內更新本檔，標明該功能屬 ✅／⚠／➕。
2. **每次執行 `gen_codemap.py`** 後，看 `CODEMAP.md` 第 6 節有沒有新出現「只有一邊能寫」的表，有就代表可能產生新差異，要在本檔登記。
3. **⚠ 項目由你決定**：決定後在 DECISIONS 新增一筆（補另一邊，或列為例外），並把本檔該列移到 ✅。
4. 掃描限制：用變數當表名的寫入、經 Edge Function 才寫入的表，腳本掃不準，以本檔人工查證為準。
