# 決議紀錄

格式：日期｜主題｜決議｜原因。日期為討論當天；較早的決議日期標「早期」。

## 工作原則
- **每個功能手機（LIFF）與 Dashboard 兩邊都要有**，並在交付時說明對照；例外僅限 FEATURES.md 最後一節列的項目。
- 新增／改名 Edge Function 要同步更新 deploy workflow。
- 「先討論／先確認再行動」＝只討論，不動手改。
- 推送前先跑 `git diff`。
- 交付一律使用真實資料夾名稱（`Dashboard/index.html`、`event-registration/...`、`SQL/NN-*.sql`）。

## 行事曆
- **重複匯入**：時間與內容完全相同的行事曆項目視為重複，匯入時略過。
- **壇篩選**：選擇某壇時，只顯示該壇的項目；**全域項目維持顯示**（行事曆、仙佛紀念日、初一十五）。壇是可擴增的選項，不寫死。

## 壇各組功能（2026-10）
- **工作細則**不是工作項目，而是每個項目裡的**實作細節**，採 6W 簡流表（When／What／Who／Where／How／Why）。
- **交接項目**：每組一份清單，換組時逐項確認。
- **組別調換**：輪替時**一次整組對調**（天廚、庶務、佛堂會隨時間互換），由組長管理；兩邊都有的人留在兩組。
- **多組**：沿用現狀，一個人可同時在多個組。
- 只有全域管理者能設定組長；組長可新增／移除組員。

## 匯出（2026-10）
- 開班參加名單 Excel 的格式以使用者提供的範本為準；範本中的「天職欄位」（點傳師…小天使）屬於格式本身，不是使用者新增的自訂欄位。
- **自動排序只留兩種**：預設「依性別及天職」、另一種「依報名時間」。（曾做過「不排序」「只依天職」，已移除。）
- 天職順序：點傳師、壇主、副壇主、講師、辦事人員、道親、班員、補課、旁聽、無。童／女的天職只會是小天使。
- 匯入範本時盡量帶入所有有值的儲存格與公式；公式的列號轉成相對於資料首列／末列的記號，列數改變時自動調整。
- 匯出的「加入天職欄位」勾選框已刪除；匯入的範本若有天職欄位則照樣保留。

## 資料刪除（2026-10-09）
- Dashboard 刪除活動、工作範本、活動流程是**真刪除**；外鍵全為 `ON DELETE CASCADE`（刪活動會連帶刪報名、住宿提供與需求等；刪工作範本會連帶刪已排出的工作與子任務範本）。
- 評估過「軟刪除」與「加強刪除確認」，**決定都不做**。誤刪只能靠 Supabase 備份或事前匯出的檔案還原。
